## 3. 代码审查发现

### 3.1 CRITICAL（8 个）

#### C-1: 前后端 Schema 不一致 — `LibraryUploadParseOptions`

- **文件**: `backend/app/schemas/library.py` vs `frontend/src/app/types/library.ts`
- **问题**: 前端类型多出 `parseOptions` 字段，后端 Pydantic 模型只有 `parserName` 和 `contentFormat`。用户上传时选择的解析参数会被**静默丢弃**。
- **修复**: 后端增加 `parseOptions` 字段，或前端移除该字段。

#### C-2: `_parse_upload_options` 静默吞掉所有异常

- **文件**: `backend/app/api/routes/library.py`, `_parse_upload_options` 函数
- **问题**: `except Exception: return None` 捕获所有错误，用户传入无效 JSON 无任何反馈。
- **修复**: 至少增加 `logging.warning` 记录异常详情。

#### C-3: 运算符优先级 Bug — `as` 与 `??` 混用

- **文件**: `frontend/src/app/pages/P16_LibraryDetail.tsx:557`
- **问题**: `as "markdown" | "text" ?? "text"` 中 `as` 优先级高于 `??`，行为不符合预期。
- **修复**: `(contentFormat ?? "text") as "markdown" | "text"`

#### C-4: `ReactMarkdown` XSS 风险

- **文件**: `frontend/src/app/components/rag/TextPreview.tsx:148`
- **问题**: 未使用 `rehype-sanitize` 插件，文档内容可能通过 markdown 链接注入。
- **修复**: 添加 `rehype-sanitize` 插件。

#### C-5: `TextPreview` 预览加载静默吞错

- **文件**: `frontend/src/app/components/rag/TextPreview.tsx:66, 90`
- **问题**: 两处 `.catch(() => {})` 导致加载失败时用户看到"暂无预览内容"而非错误提示。
- **修复**: 添加错误状态并展示给用户。

#### C-6: 前端 `LibraryUploadParseOptions` 类型与后端不匹配

- **文件**: `frontend/src/app/types/library.ts:216-220`
- **问题**: 前端类型多出 `parseOptions` 字段（与 C-1 同一问题的不同视角）。
- **修复**: 删除前端类型中的 `parseOptions` 字段。

#### C-7: `/{documentId}/text` 端点未在接口设计说明中记录

- **文件**: `docs/03-系统设计/接口设计说明.md`
- **问题**: 新端点支持 preview/full/chunks 三种 mode 和 parseRevisionId 参数，有三种响应类型，但文档完全缺失。
- **修复**: 在 5.6 节和 6 节补充完整接口说明。

#### C-8: `parse_revisions` 表未在数据库设计说明中记录

- **文件**: `docs/03-系统设计/数据库设计.md`
- **问题**: 该表是解析版本的核心存储，但 4.4 节表清单中完全缺失。
- **修复**: 在 4.4 节添加表结构说明。
