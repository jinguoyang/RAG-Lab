## 1. 当前结论

- 托管方式：采用“同一 PostgreSQL 实例，新建独立 DB”的方式，不使用 schema。
- DB 命名建议：`ext_training_<appId前8位>`。
- 嵌入页触发条件：只有员工培训智能应用在创建时启用嵌入页，才创建内置子程序部署记录。
- 未启用嵌入页：只保留智能应用 API Key 接入能力，不创建子程序 DB，不启动前后端。
- 内置系统 Key：
  - 页面可见。
  - 标识为系统管理。
  - 不允许删除。
  - 保持 `active`。
  - 关闭嵌入页或停用子程序时不删除。
- 部署状态：
  - 由 `embedded_app_deployments` 类表记录。
  - Key 身份和 deployment 运行状态分离。
  - 后续监控页读取部署状态、端口、DB、进程、健康检查和错误信息。
- 配置注入：
  - 单实例默认注入目标为 `external-training-app/backend/.env`。
  - 多实例托管时必须使用实例级 `.env`，例如 `runtime/embedded-apps/<appId>/backend/.env`，不能多个应用共用同一个 `.env`。
- 运行独立性：
  - 子程序进程应独立于主程序进程。
  - 主程序挂掉不主动杀掉子程序；子程序挂掉也不影响主程序普通 API 能力。
  - 子程序智能能力依赖主程序 API，主程序不可用时子程序页面可打开但平台调用失败。
- 重启策略：
  - 子程序按 Docker / Docker Compose 部署，兼容 Windows 运行环境。
  - 子程序异常退出由 Docker Compose `restart: unless-stopped` 自动重启。
  - 主程序运维页负责展示状态，并提供启动、停止、重启和健康检查动作。

```powershell

git diff --check
```

### 阶段 2：主程序侧最小闭环

- 创建员工培训智能应用，未勾选嵌入页时：
  - 应用创建成功。
  - 不创建 deployment。
  - 不自动启动子程序。
- 创建员工培训智能应用，勾选嵌入页时：
  - 自动创建 `embedded_system` Key。
  - Key 在页面可见。
  - Key 不可删除。
  - 创建 `pending` deployment 记录。
  - 记录 `database_name`、`backend_port`、`frontend_port`。

验收命令：

```powershell
python -m pytest backend/app/tests/unit/test_rag_app_scenario_metadata.py -q
```

### 阶段 3：部署执行器

- 创建独立 DB。
- 执行 external-training-app Alembic 迁移。
- 生成后端运行配置。
- 注入 `EXT_TRAINING_PLATFORM_API_KEY`。
- 写入 `external-training-app/backend/.env` 或实例级 `runtime/embedded-apps/<appId>/backend/.env`。
- 生成 `runtime/embedded-apps/<appId>/docker-compose.yml`。
- 通过 Docker Compose 启动后端和前端容器。
- 使用 `restart: unless-stopped` 保持子程序独立运行和异常自动重启。
- 健康检查通过后将 deployment 置为 `running`。

验收命令：

```powershell
python -m pytest backend/app/tests/unit/test_embedded_app_deployment_service.py -q
```

## 5. 风险记录

| 风险 | 当前处理 |
| --- | --- |
| 生产库正在使用 | 当前只写文档，不执行库变更 |
| 迁移脚本未来执行风险 | 必须单独确认执行窗口，且只允许新增 |
| 内置 Key 误删 | 后续服务层必须拒绝 `embedded_system` Key 删除 |
| 子程序端口冲突 | 端口分配必须同时查部署记录和 socket bind |
| 子程序停用但 Key active | 页面入口由 deployment 状态控制，不由 Key 控制 |
| 明文 Key 保存风险 | 主程序只保存 hash，明文只注入子程序配置或 secret |
| 多实例 `.env` 覆盖 | 多实例必须使用 `runtime/embedded-apps/<appId>/backend/.env` 一类实例级配置 |
| 主程序挂掉影响子程序 | 进程层面不互相杀掉；业务调用失败由子程序页面提示 |
| 子程序挂掉后恢复 | Docker Compose 自动重启，主程序运维页提供手动重启和健康检查 |
| Windows 兼容 | 不使用 systemctl/nohup/setsid；通过 Docker Desktop 或兼容 Docker CLI 的运行时管理 |
