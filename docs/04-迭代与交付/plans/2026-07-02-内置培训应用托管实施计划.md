# 内置培训应用托管 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
>
> 本文为开发计划活文档，位置按本项目 `AGENTS.md` 约定存放在 `docs/04-迭代与交付/plans/`。本计划只描述后续实现步骤，不代表当前已经执行数据库迁移；执行阶段必须先获得“可以改库”的明确确认。

**Goal:** 支持主程序在创建员工培训智能应用时，按“是否启用嵌入页”决定是否自动托管内置 `external-training-app`，并通过系统管理 API Key、独立 PostgreSQL 数据库、端口分配和部署状态记录完成闭环。

**Architecture:** 主程序仍是智能应用、API Key、调用审计、会话和 QARun 的真值中心；`external-training-app` 是可选内置子程序，只保存培训应用自身业务数据。启用嵌入页时，主程序为该应用生成不可删除的系统 Key，记录独立 DB 名、端口和运行状态；未启用嵌入页时只提供普通 API Key 接入能力，不创建子程序 DB，不启动前后端。

**Tech Stack:** FastAPI、SQLAlchemy、Alembic、PostgreSQL、React、Vite、TypeScript、Docker、Docker Compose、PowerShell、socket 端口探测。

---

## 1. 关键假设

- PostgreSQL 采用“同一实例、新建独立 DB”的方式托管子程序，不使用 schema。
- 内置嵌入系统 Key 属于长期身份，`status` 保持 `active`，不允许删除；关闭嵌入页或停用子程序只改变部署状态。
- 内置 Key 明文只在系统内部用于写入 `external-training-app` 后端配置，不作为普通用户复制使用的凭据。
- 主程序侧调用记录、会话、QARun、审计仍按 `app_id` 和 `api_key_id` 归集。
- 本计划执行前不能修改生产数据库结构；涉及迁移的任务必须单独确认执行窗口。

- [ ] **Step 7: 固化子程序独立运行边界**

进程边界：

```text
1. 主程序进程不长期持有子程序进程。
2. 主程序重启或挂掉，不主动杀掉已运行的 external-training-app。
3. 子程序挂掉，不影响主程序 API、智能应用管理和普通 API Key 调用。
4. 子程序智能能力依赖主程序 API；主程序不可用时，子程序页面可打开但平台调用失败。
```

故障影响矩阵：

```text
主程序正常 + 子程序正常 -> 页面和智能能力均正常
主程序挂掉 + 子程序正常 -> 页面可打开，调用平台接口失败
主程序正常 + 子程序挂掉 -> 嵌入页不可访问，主程序 API 正常
主程序挂掉 + 子程序挂掉 -> 全部不可用
```

## 5. 风险与控制

| 风险 | 控制 |
| --- | --- |
| 生产库正在使用 | 迁移只新增字段和新表；执行前必须确认窗口和备份 |
| 端口冲突 | 部署表唯一约束 + socket bind 双重检测 |
| 系统 Key 误删 | `deletable=false` + 服务层删除保护 |
| 子程序停止但 Key active | 页面用部署状态控制入口，Key 仅表示长期身份 |
| DB 数量增长 | 后续运维监控页展示 DB、端口、健康状态和错误信息 |
| 明文 Key 泄露 | 主程序只保存 hash；明文只注入子程序配置 |
