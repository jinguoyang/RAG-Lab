# 交互式教学有效性改进计划

> 用途：本文是活文档，承接 E33 员工培训 Agent 的交互式教学有效性改进。当前 Backlog 状态以 `docs/04-迭代与交付/产品待办清单.md` 为准；本文只记录目标、范围、实施顺序和验收口径。

## 1. 目标

将当前“按文档展示单个 Chunk、按固定状态连续点击”的课堂，改造成“按学习目标组织小节、由智能体综合讲解、以 Checkpoint 验证掌握情况”的交互式课堂。

完成后应满足：

- 小节由可验证的学习目标决定，不再默认一个文档等于一个小节。
- 一个小节可以引用多个文档和多个 Chunk；短课程可以只有一个小节。
- 教学正文是智能体基于证据生成的解释、案例和重点总结，不直接搬运 Chunk。
- Checkpoint 与当前小节学习目标直接对应，无法生成有效题目时不得用固定正确题代替。
- 非末节只允许进入下一节或保存退出，不能展示不可执行的“完成课程”按钮。
- 未通过 Checkpoint 的小节不能计入完成，必须经过针对性讲解并重新验证。

## 2. 关键假设

- ex-app 继续保存最终学习计划、员工绑定和课程业务真值，平台不恢复学习计划审批职责。
- 平台负责生成结构化小节草稿、校验证据范围、执行课堂状态机、生成讲解与 Checkpoint 反馈。
- ex-app 创建课堂会话时，通过现有 `inputs` 传入冻结的课程快照；平台验证快照中的文档均属于当前 App 可访问知识库。
- 首轮只实现课程级顺序学习，不实现自由跳节、个人掌握度模型、复杂自适应推荐和证书体系。
- 保留现有领域 Controller 作为唯一权威状态机；可减少用户可见步骤，但不绕过服务端完成判定。

## 3. 当前问题基线

| 问题 | 当前表现 | 改进方向 |
| --- | --- | --- |
| 小节等于文档 | `readingOrder` 中每个文档被直接作为一节 | 新增结构化 `sections`，按学习目标组织 |
| 教学内容搬运 Chunk | 课堂截取单个证据片段作为正文，封面和附录标题也可能进入课堂 | 多证据检索后生成结构化教学讲解 |
| 测验无诊断价值 | 无已发布题目时返回固定正确判断题 | 有效 Checkpoint 或明确阻断 |
| 用户步骤机械 | `TEACH -> CHECK_UNDERSTAND -> QUIZ -> GRADE -> REVIEW -> SUMMARY` 多次只需点击继续 | 合并无信息增量的用户可见步骤 |
| 完成按钮自相矛盾 | 非末节展示“完成课程”，点击后服务端拒绝 | 非末节不返回也不渲染完成按钮 |
| 未通过仍可推进 | 未通过后仍可“完成复习”并进入下一节 | 通过 Checkpoint 才能完成小节 |

## 4. 目标数据契约

学习计划草稿新增 `sections`。每个小节至少包含：

```json
{
  "sectionId": "stable-id",
  "title": "识别生产现场环境风险",
  "learningObjective": "学员能够识别三类环境风险并说明对应处置原则。",
  "sourceDocumentIds": ["document-id-1", "document-id-2"],
  "evidenceChunkIds": ["chunk-id-1", "chunk-id-2"],
  "keyPoints": ["风险类型", "适用条件", "处置原则"],
  "checkpointCriteria": ["能识别风险", "能选择正确处置"],
  "estimatedMinutes": 8,
  "required": true
}
```

约束：

- `sectionId` 由程序生成或归一化，不能使用标题作为稳定标识。
- `sourceDocumentIds` 和 `evidenceChunkIds` 必须属于当前 App 可访问范围。
- 小节数量由内容和学习目标决定，不设置固定数量。
- `readingOrder` 继续表示文档推荐顺序，用于兼容现有计划编辑；课堂执行顺序以 `sections` 为准。
- ex-app 保存管理员审核后的 `sections`，创建课堂时将其作为冻结课程快照传给平台。

## 5. 目标课堂流程

用户可见流程收敛为：

```text
课程导览
  -> 教学讲解 <-> 自由追问
  -> 小节 Checkpoint
     -> 通过：小节完成 -> 下一节 / 保存退出
     -> 未通过：针对性讲解 -> 再次 Checkpoint
  -> 全部必修小节完成
  -> 完成课程
```

后台可以继续保留 `GRADE`、`REVIEW` 等内部状态用于审计和恢复，但不要求用户为没有信息增量的状态单独点击按钮。

## 6. 实施阶段

### 阶段一：修复错误交互与虚假通过

目标：先消除会误导用户或产生虚假学习结果的行为，不引入新数据模型。

改动范围：

- 后端非末节 `SUMMARY` 只返回“下一节”或“保存退出”，不返回 `complete`。
- 前端完全按平台 `uiActions` 渲染，不在 `SUMMARY` 无条件额外渲染按钮。
- 删除固定正确的 `inline-true-false` 兜底题。
- 当前小节没有可用 Checkpoint 时，返回“课堂内容尚未准备完成”，禁止计入完成。
- 未通过 Checkpoint 时移除可直接推进小节的动作。

验收标准：

- 非末节响应和页面均不存在“完成课程”。
- 用户无法通过固定答案或空复习流程完成小节。
- 最后一节且全部必修小节通过后，才允许完成课程。

主要文件：

- `backend/app/services/training_classroom_service.py`
- `backend/app/tests/unit/test_training_classroom_section_boundary.py`
- `backend/app/tests/integration/test_training_e2e_acceptance.py`
- `external-training-app/frontend/src/pages/ClassroomPage.tsx`

### 阶段二：结构化小节生成与审核

目标：让课程结构从文档顺序升级为学习目标驱动的小节。

改动范围：

- 扩展平台学习计划草稿 DTO，增加 `sections`。
- 调整学习计划生成 Prompt：先识别学习目标，再决定是否拆节及拆成几节。
- 程序校验小节、文档、Chunk 和 Checkpoint 标准之间的引用关系。
- ex-app 保存并允许管理员审核小节标题、目标、顺序、预计时间和必修标记。
- 创建课堂会话时传入冻结课程快照，平台校验后写入会话 metadata。
- 没有 `sections` 的旧计划采用兼容模式，但明确标记为旧版文档级课堂，不伪装成目标驱动小节。

验收标准：

- 同一小节可以引用多个文档；同一文档可以被多个小节引用。
- 内容较短时允许只生成一个小节。
- 管理员可以在 ex-app 调整小节结构后保存。
- 课堂章节总数来自冻结快照中的 `sections`，不再由文档数或召回 Chunk 数推算。

主要文件：

- `backend/app/schemas/training_plan.py`
- `backend/app/schemas/training_classroom.py`
- `backend/app/services/training_plan_service.py`
- `backend/app/services/training_classroom_service.py`
- `external-training-app/backend/app/schemas/training_plan.py`
- `external-training-app/backend/app/services/training_plan_service.py`
- `external-training-app/backend/app/services/training_classroom_service.py`
- `external-training-app/frontend/src/pages/PlanDetailPage.tsx`

数据影响：

- 优先复用 ex-app 学习计划现有 JSON/metadata 字段保存 `sections`；只有现有字段无法稳定承载时才新增迁移。
- 平台课堂会话在 metadata 保存冻结快照和当前 `sectionId`，避免执行中计划被修改导致漂移。

### 阶段三：智能教学讲解与有效 Checkpoint

目标：让每一节真正完成“讲解、提问、验证、反馈”的教学闭环。

改动范围：

- 按当前小节的 `evidenceChunkIds` 和 `sourceDocumentIds` 检索多个证据。
- 新增结构化教学输出，至少包含学习目标、核心解释、适用条件、风险点、案例和 Citation。
- 对封面、目录、版本记录、空附录标题等低教学价值证据进行过滤或降权。
- Checkpoint 根据 `checkpointCriteria` 生成或选择题目，题目必须绑定当前 `sectionId` 和证据。
- 通过后自动展示简短反馈并完成小节；未通过时根据遗漏点生成针对性讲解，并要求重新验证。
- 保留自由追问和受控答疑，回答范围限定在当前小节与已学小节证据内。

验收标准：

- 教学正文不能只是证据原文截断，必须包含智能体解释和至少一个具体应用示例。
- 每个 Checkpoint 都能映射到当前小节至少一个验收标准。
- 更换当前小节后，讲解、题目、反馈和 Citation 随之变化。
- 未通过反馈明确指出遗漏点，并引用对应证据。

主要文件：

- `backend/app/services/training_classroom_service.py`
- `backend/app/services/training_question_service.py`
- `backend/app/services/training_llm_service.py`
- `backend/app/tests/integration/test_employee_training_agent_runtime.py`
- `backend/app/tests/integration/test_employee_training_graph_orchestration.py`

### 阶段四：课堂体验收敛与真实内容验收

目标：减少机械点击，并用真实课程内容验证教学有效性。

改动范围：

- 前端展示课程进度、小节目标、预计时长、Checkpoint 状态和“保存退出”。
- 合并没有信息增量的用户可见步骤；服务端内部状态和审计记录继续保留。
- 补充断线恢复：恢复当前小节、讲解内容、待答 Checkpoint 和已完成小节。
- 使用至少两组真实课程样本验收：
  - 多文档组成一个学习目标的小节。
  - 一个长文档拆成多个学习目标小节。
- 增加内容质量人工评审表，记录小节合理性、讲解完整性、题目有效性和引用准确性。

验收标准：

- 正常通过一个小节时，不需要经过重复的“确认理解”和空泛“复习建议”点击。
- 关闭并重新进入课堂后，可恢复到同一 Checkpoint。
- 两组真实样本均不存在封面、目录或版本记录被当作主要教学内容的情况。
- 人工评审确认题目无法在不阅读讲解的情况下靠固定套路稳定答对。

主要文件：

- `external-training-app/frontend/src/pages/ClassroomPage.tsx`
- `external-training-app/frontend/src/services/classroomService.ts`
- `backend/app/tests/integration/test_training_e2e_acceptance.py`
- `docs/05-测试与验收/`

## 7. 不做范围

- 不建设个人知识点掌握度画像。
- 不实现基于用户画像的复杂自适应推荐。
- 不新增自由跳节、跳过必修小节或管理员强制完成课程。
- 不把课堂临时生成题作为课后认证题。
- 不重构通用 Agent Runtime 或替换现有课堂领域 Controller。
- 不顺带清理与课堂有效性无关的历史状态、旧接口或前端页面。

真实内容验收不能只使用 mock 或固定 fixture。至少保留两份课堂事件记录，并人工检查：

- 小节是否由学习目标而不是文档数量决定。
- 教学讲解是否包含总结、解释、案例和证据。
- Checkpoint 是否真正验证当前目标。
- 未通过后的反馈是否针对用户遗漏点。
- 只有全部必修小节通过后才能完成课程。
