# 课前数据链路完善计划

> 用途：本文是活文档，承接员工培训 Agent 的课前学习计划、题库生成、交互式学习和课后测验新口径。当前状态仍以 `docs/04-迭代与交付/产品待办清单.md` 为准；本文只记录本轮需求边界、接口调整和验收口径。

## 1. 关键假设

- 外部培训应用简称 `ex-app`，它负责保存最终学习计划、计划名称和员工绑定关系。
- 平台侧不再审批学习计划；平台只生成学习计划草稿、提供知识库文档查询和题库/课堂/评分能力。
- 题库记录由 ex-app 保存；平台只负责按文档生成题目草稿和主观题评分能力。
- 平台侧生成题库时按学习计划选择的文档逐个生成，默认每个文档 10 道题，可通过启动环境变量调整。
- 课后测验默认每个文档抽 5 道题，可通过启动环境变量调整；抽题比例按选择、判断、主观题 4:4:2 近似分配。

## 2. 本次范围

### 2.1 学习计划生成

1. ex-app 管理员输入岗位、简介和可选计划名称。
2. 平台根据 App API Key 反查应用和知识库，筛选相关文档，返回文档 `id`、文档名称、分类和难度等草稿信息。
3. ex-app 管理员可调整顺序、分类、难度并增删文档。
4. 平台提供知识库文档查询接口，支持 ex-app 在编辑计划时检索和补充文档。
5. 最终学习计划、计划名称和员工绑定关系保存在 ex-app。

### 2.2 题库生成与审核

1. ex-app 将最终学习计划中选中的文档 ID 提交给平台生成题目。
2. 平台逐个文档生成题目，默认每文档 10 道。
3. 题型为 `single_choice`、`true_false`、`subjective`，比例为 4:4:2。
4. 主观题满分 5 分，rubric 最多 5 个考点，每个考点名称尽量不超过 10 个汉字。
5. 题目必须包含答案、解析和参考资料；主观题答案说明考点和得分关系。
6. 题目由 ex-app 保存，状态从 `draft` 开始；管理员审核通过后直接变为 `published` 并进入本地正式题库，审核不通过则物理删除草稿。
7. 自动生成由学习计划保存或新增文档触发；只要文档已有 `draft` 或 `published` 题目，就不再自动生成。
8. 管理员可在题目审核页针对单个文档手动再次生成一批草稿；手动生成不执行重复生成控制。
9. 正式题库页面仅展示 `published` 题目，支持修改和物理删除。

### 2.3 交互式学习

1. 学员先浏览计划内文档，再选择一个文档开始学习。
2. 平台按章节组织教学内容，不能只罗列 chunk。
3. 法律规则类内容需要细讲规则、适用条件、例外和风险点。
4. 课堂可根据用户反馈调整讲解速度、补充解释和示例，但不能跳章节或省略教学内容。
5. 每个课堂末尾用少量随堂测评收尾。

### 2.4 课后测验

1. 学员学完某个文档后，才允许发起该文档课后测验。
2. 课后测验由 ex-app 从本地已审核题库抽题，默认每文档 5 道。
3. 抽题仍按 4:4:2 近似分配；5 题时为选择 2、判断 2、主观 1。
4. 客观题由平台按标准答案评分。
5. 主观题调用平台评分接口，满分 5 分，超过 4 分算合格。
6. 只有通过课后测验后，该文档才能标注为完成学习进度。
7. 学员可对有异议题目上报，平台记录异议并暴露给管理员处理。

## 3. 不做范围

- 不把学习计划重新改回平台审批发布流程。
- 不在平台侧维护 ex-app 的员工组织、计划分配和证书体系。
- 不把课后测验题目直接从 LLM 临时生成；课后测验只能从已审核题库抽取。
- 不把课堂 Agent 输出作为业务真值；学习进度仍由程序状态机和测验结果判断。

## 4. 接口调整建议

| 能力 | 接口 | 说明 |
| --- | --- | --- |
| 计划草稿生成 | `POST /api/v1/training/plans/drafts` | 返回候选文档和推荐顺序；不提供审批、拒绝语义 |
| 文档查询 | `GET /api/v1/training/documents` | 按关键词、分类、难度查询当前 App 知识库文档 |
| 题库生成 | `POST /api/v1/training/questions/drafts` | 平台返回题目草稿内容；ex-app 写入本地题库并分配本地题目 ID |
| 主观题评分 | `POST /api/v1/training/post-quizzes/subjective-grading` | ex-app 传题干、答案、rubric 和证据，平台不接收题库 `questionId` |
| 课堂会话 | `POST /api/v1/training/classroom/sessions` | 指定 ex-app 计划 ID 和文档 ID 开始学习 |

ex-app 本地接口：

| 能力 | 接口 | 说明 |
| --- | --- | --- |
| 题目审核 | `POST /api/v1/training/questions/{questionId}/review` | 审核通过直接发布，审核不通过物理删除草稿 |
| 题目修改 | `PATCH /api/v1/training/questions/{questionId}` | 修改 ex-app 本地题目内容 |
| 题目删除 | `DELETE /api/v1/training/questions/{questionId}` | 从 ex-app 本地题库物理删除题目 |
| 课后测验开始 | `POST /api/v1/training/post-quizzes` | 从 ex-app 本地题库按文档抽题 |
| 课后测验提交 | `POST /api/v1/training/post-quizzes/{quizId}/submissions` | ex-app 本地记录答案和结果；主观题调用平台评分能力 |
| 题目异议 | `POST /api/v1/training/questions/{questionId}/appeals` | 学员向 ex-app 上报有异议题目 |
| 异议处理 | `POST /api/v1/training/questions/appeals/{appealId}/resolve` | ex-app 管理员处理题目异议 |

## 5. 已先行落地

- 后端配置新增 `RAG_LAB_TRAINING_QUESTIONS_PER_DOCUMENT`，默认 `10`。
- 后端配置新增 `RAG_LAB_TRAINING_POST_QUIZ_QUESTION_COUNT`，默认 `5`。
- 平台题库生成支持请求不传 `count` 时读取默认每文档题数。
- 平台题库生成按 `documentIds` 逐个文档生成题目，并在题目元数据和响应中保留 `documentId`。
- 平台题库回退题型序列改为 4:4:2；10 题为 4/4/2，5 题为 2/2/1。
- 平台主观题 rubric 规范为 5 分制，最多 5 个考点。
- 已新增 `GET /api/v1/training/documents`，供 ex-app 编辑学习计划时查询当前 App 知识库文档。
- ex-app 题目审核、修改、删除、课后测验抽题/提交、题目异议上报和异议处理均已切换为本地表读写。
- ex-app 题目审核采用 `draft -> published` 两状态流程；审核不通过直接物理删除。
- 自动生成只对已有 `draft/published` 题目的文档去重；题目审核页手动生成不去重。
- 平台已新增 `POST /api/v1/training/post-quizzes/subjective-grading`，供 ex-app 主观题评分时传题目内容和 rubric，不传平台题库 `questionId`。
- 课后测验通过后会在 ex-app 本地课堂会话元数据中记录 `completedDocumentIds`，用于文档级完成标记。
- ex-app 已接入学习计划编辑保存、文档查询增删、员工绑定、题目生成/编辑/审核、课后测验提交和异议上报页面链路。

## 6. 后续待办

1. 学习计划 `publish/reject` 平台旧接口仅保留兼容，ex-app 新流程不再使用；后续可在版本窗口统一标记废弃。
2. ex-app 课堂页当前先完成最小可用链路，后续可补充计划内多文档显式选择和更细的测验结果展示。
