# V1.8 RAG 应用化封装规划

## 1. 版本目标

V1.8 聚焦“把治理后的 RAG 能力发布为可调用应用”：在不削弱现有 RAG 调试、治理和评估能力的前提下，新增 RAG 应用定义、App API Key、外部对话运行时、会话记录、调用审计和质量回流。

目标不是复刻 Dify 的通用工作流平台，而是让外部 Web 应用可以快速接入受控 RAG 查询对话，并继续使用 RAG-Lab 更深入的配置治理、权限裁剪、Trace、Citation、评估和优化闭环。

实施拆分见：[RAG App Runtime Implementation Plan](../plans/2026-05-14-rag-app-runtime.md)。

## 4. 边界

- 不建设自由 DAG、插件市场、复杂 Agent 工作流或通用低代码平台。
- 不建设公网匿名聊天站点；外部调用必须通过应用级凭据和配置绑定进入。
- 不绕过知识库权限、Chunk 权限、Graph 回落和 Citation 安全规则。
- 不把外部会话记录替代 QARun；QARun 仍是 RAG 执行、诊断和评估的事实来源。
- 不在第一版实现商业化租户、计费中心和复杂配额售卖能力。

## 5. 验收方向

- 外部 Web 应用可通过 App API Key 调用 `POST /api/v1/app-runtime/chat-messages`。
- 返回内容包含 answer、citations、conversationId、messageId、runId、usage 和安全 metadata。
- 平台内部可以从 App Invocation 追溯到 QARun，并查看完整 Trace、Evidence、Citation 和 Metrics。
- 禁用应用、禁用 key、停用知识库、缺少 active revision 或无授权证据时有稳定错误码。
- 外部反馈可以进入 QARun 反馈或 EvaluationSample，用于后续评估与配置优化。

## 6. Sprint 35 验收硬化收尾

Sprint 35 完成了 V1.8 最终验收闭环，覆盖以下能力：

- **前端工程化**：ESLint 9 扁平配置 + Vitest 单元测试（Pipeline diff 用例），`npm run lint` / `npm run test` / `npm run build` 均通过。
- **App Runtime 前端服务层**：blocking、streaming（SSE 解析）、反馈回流调用封装，Bearer API Key header，不持久化明文。
- **P13 真实 Runtime 试运行**：试运行面板读取真实 App API Key，调用 `/api/v1/app-runtime/chat-messages`，展示 answer、Citation、runId、messageId 和 usage。
- **P13 调用统计与状态筛选**：应用级调用统计、服务端状态筛选、API Key 过期时间管理。
- **P13→P10 跳转闭环**：调用记录按 runId 跳转到 P10 QA 历史，自动打开关联 QARun 详情。
- **App Conversation/Message 详情**：只读详情接口和 P13 会话时间线视图，保留 QARun 跳转。
- **浏览器 E2E 验收脚本**：覆盖创建应用→生成完整 Key→blocking Runtime 调用→反馈回流→撤销 Key→撤销后调用失败验证。
- **真实 Provider E2E 验收**：真实上传文本→入库→App Runtime 调用→citationCount=1，回查 PostgreSQL Chunk 确认 marker 存在。

### 验收结论

V1.8 所有 P0 和 P1 Backlog（B-133 至 B-155）已全部 Done。真实 Provider 网络级复测（Embedding、Milvus、OpenSearch、Neo4j、LLM、Rerank）已在 Sprint 32 和 Sprint 35 通过，证据保存在 `docs/06-发布与运维/V1.8-Provider网络级复测记录.json`。切换测试或预生产环境后仍需重新执行网络级复测。
