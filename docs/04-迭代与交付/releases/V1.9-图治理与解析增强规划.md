# V1.9 图治理、解析增强与 RAG App 运行治理规划

## 1. 版本目标

V1.9 聚焦三项增强能力：知识库图快照的保留治理、文档解析后端的能力提升，以及既有 RAG App Runtime 的运行治理与接入可见性。

- **E23 图快照保留与配置治理**：让 `graph_snapshots`、`graph_chunk_refs` 和 Neo4j 中的图快照数据具备可配置的保留策略、清理作业、审计记录和页面可见能力，避免图数据无限膨胀。
- **E24 文档解析能力增强**：收口当前解析依赖，引入 MarkItDown 作为 DOCX/XLSX 统一 Markdown 解析后端，并评估 MinerU 作为复杂版式 PDF 的可选增强链路。
- **E27 RAG App 运行治理与接入可见性**：补强调用记录生命周期、运行中监控、应用级并发上限和 P13 API 调用文档，让试运行和真实 API 调用都具备一致审计与接入说明。

V1.9 不新增 RAG App 类型或新对话模式、不新增商业化能力、不引入新的外部服务依赖（MarkItDown 和 MinerU 为可选增强，不改变默认链路）；允许补强既有 Runtime 的观测、限流和接入文档。

## 4. 边界

- 不新增 RAG App 类型或对话模式；仅补强既有 Runtime 的审计、并发控制和接入说明。
- 不引入商业化租户、计费中心或复杂配额能力。
- 不改变默认文档解析链路（pypdf + Markdown 切块）；MarkItDown 和 MinerU 为可选增强，需显式配置启用。
- 图快照清理作业为异步执行，不阻塞在线请求；清理前应有预览和确认机制。
- 不引入新的基础设施依赖（MarkItDown 和 MinerU 为 Python 包，pip install 即可）。
- App Runtime 超过并发上限时直接返回 429，不做请求排队；后续若需要排队，应另行设计异步 Runtime 契约。

## 5. 验收方向

### E23 验收方向

- 图快照保留策略可配置（保留数量、保留天数、自动清理开关），默认策略对现有知识库生效。
- 清理作业异步执行，同步清理 PostgreSQL `graph_snapshots` / `graph_chunk_refs` 和 Neo4j 图对象。
- 清理完成后在审计日志中留下记录，包含清理数量、目标知识库和执行时间。
- P08 配置管理页面可查看当前策略、触发手动清理预览和查看清理历史。

### E24 验收方向

- MarkItDown 可解析 DOCX 和 XLSX 文件，输出 Markdown 格式，复用现有 Markdown 切块链路。
- PDF 解析器对比脚本可输出 pypdf / MarkItDown / MinerU 在页码、章节、表格、OCR 和耗时维度的评估报告。
- MinerU 评估脚本可对复杂版式、表格和扫描 PDF 输出解析质量结论。
- 默认解析链路不受影响，未配置 MarkItDown / MinerU 时行为不变。

### E27 验收方向

- App Runtime 在有效 App/Key 解析后立即写入 `app_invocations.status = running`，完成后更新为 `success` 或 `failed`。
- 应用配置 `metadata.runtimeLimits.maxConcurrent` 后，超过运行中调用上限的请求返回 HTTP 429 和 `RAG_APP_CONCURRENCY_EXCEEDED`，并写入 failed invocation。
- P13 调用记录可筛选和展示运行中调用，统计区展示运行中数量和并发拒绝次数。
- P13 提供 API 调用文档弹出层，覆盖调用地址、鉴权、blocking/streaming、反馈接口、返回字段、错误码和安全注意事项。
