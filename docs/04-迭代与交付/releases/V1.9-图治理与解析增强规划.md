# V1.9 图治理与解析增强规划

## 1. 版本目标

V1.9 聚焦两项内部增强能力：知识库图快照的保留治理和文档解析后端的能力提升。

- **E23 图快照保留与配置治理**：让 `graph_snapshots`、`graph_chunk_refs` 和 Neo4j 中的图快照数据具备可配置的保留策略、清理作业、审计记录和页面可见能力，避免图数据无限膨胀。
- **E24 文档解析能力增强**：收口当前解析依赖，引入 MarkItDown 作为 DOCX/XLSX 统一 Markdown 解析后端，并评估 MinerU 作为复杂版式 PDF 的可选增强链路。

V1.9 不扩展 RAG App 功能、不新增商业化能力、不引入新的外部服务依赖（MarkItDown 和 MinerU 为可选增强，不改变默认链路）。

## 4. 边界

- 不扩展 RAG App 功能、不新增 App 类型或对话模式。
- 不引入商业化租户、计费中心或复杂配额能力。
- 不改变默认文档解析链路（pypdf + Markdown 切块）；MarkItDown 和 MinerU 为可选增强，需显式配置启用。
- 图快照清理作业为异步执行，不阻塞在线请求；清理前应有预览和确认机制。
- 不引入新的基础设施依赖（MarkItDown 和 MinerU 为 Python 包，pip install 即可）。

## 5. 验收方向

### E23 验收方向

- 图快照保留策略可配置（保留数量、保留天数、自动清理开关），默认策略对现有知识库生效。
- 清理作业异步执行，同步清理 PostgreSQL `graph_snapshots` / `graph_chunk_refs` 和 Neo4j 图对象。
- 清理完成后在审计日志中留下记录，包含清理数量、目标知识库和执行时间。
- P08 配置管理页面可查看当前策略、触发手动清理预览和查看清理历史。

### E24 验收方向

- MarkItDown 可解析 DOCX 和 XLSX 文件，输出 Markdown 格式，复用现有 Markdown 切块链路。
- PDF 解析器对比脚本可输出 pypdf / MarkItDown / MinerU 在页码、章节、表格、OCR 和耗时维度的评估报告。
- MinerU 评估脚本可对复杂版式、表格和扫描 PDF 输出解析质量结论。
- 默认解析链路不受影响，未配置 MarkItDown / MinerU 时行为不变。
