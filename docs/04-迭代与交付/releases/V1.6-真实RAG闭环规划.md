# V1.6 真实 RAG 闭环规划

## 1. 版本目标

V1.6 聚焦“真实文档可用”：用户上传真实文档后，系统必须完成真实解析、Chunk 切分、多副本索引、检索查询、答案生成、监控诊断和历史回放复跑。版本验收不再只证明单个模块具备能力，而是证明一条真实 RAG 主链路可以稳定跑通并可复盘。

## 3. 边界

- 不建设公网聊天产品、多轮记忆或复杂会话工作台。
- 不引入新的向量数据库、搜索引擎或图数据库选型。
- 不允许真实链路失败时静默退回 mock/local 并标记成功。
- 不以页面展示代替后端权限裁剪；Evidence 和回放复跑仍以当前权限为准。
- 不在本版本扩展复杂 RAG 节点配置；节点模块化深化放入 V1.7。

## 4. 验收方向

- 使用 `docs/examples/` 中至少一个真实文档完成上传、解析和 Chunk 落库。
- 同一批 Chunk 能追溯到 PostgreSQL 真值，并同步到 Milvus、OpenSearch 和 Neo4j 副本或明确记录环境不可用原因。
- P09 基于该文档完成一次真实 QA，Answer 使用授权 Evidence 生成，Citation 可定位到文档、版本、页码或章节和 Chunk。
- P05/P06/P07/P09/P10 能展示解析、索引、检索、生成、引用和回放阶段的状态、耗时和失败原因。
- P10 能对该真实 QA Run 执行回放复跑，并比较答案、Evidence、Citation、Trace 和配置差异。
- `verify_v16_real_rag_e2e.py` 能作为 V1.6 最小验收入口，区分代码缺口、依赖缺失和真实 Provider 环境不可用。
