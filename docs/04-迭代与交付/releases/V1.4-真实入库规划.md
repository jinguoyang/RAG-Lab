# V1.4 真实入库规划

## 1. 版本目标

V1.4 聚焦“上传后真实落地”：文档上传后必须经过真实解析、Chunk 切分、Embedding 生成，并把 PostgreSQL 主数据、Milvus 向量副本、OpenSearch 文本副本和 Neo4j 图谱副本串成可重试、可观测、可验收的入库链路。

## 3. 边界

- 不建设新的生产认证、审批流、通知中心或多租户体系。
- 不把 Milvus、OpenSearch、Neo4j 作为业务真值；PostgreSQL 仍保存 Chunk 正文和元数据真值。
- 不允许解析失败时静默生成“占位 Chunk”并标记成功；失败必须进入 IngestJob 和页面状态。
- 不要求一次覆盖所有文件格式，优先支持 txt、md、pdf、docx，并为不支持格式返回明确失败原因。
- 真实 LLM API 接入只覆盖 Embedding、Query Rewrite、图谱抽取和 Generation 所需的 OpenAI-compatible 契约，不在本版本建设 Prompt 管理平台。

## 4. 验收方向

- 上传一个真实 pdf 或 docx 后，PostgreSQL 中存在带页码、章节和 token 信息的 Chunk。
- Milvus 中存在对应 chunk_id、embedding、过滤字段和必要 metadata。
- OpenSearch 中存在对应 chunk 文本、知识库、文档、版本、密级、状态和权限过滤字段。
- Neo4j 中存在实体、关系和 ChunkRef，图谱对象可回溯到 PostgreSQL Chunk。
- IngestJob、IndexSyncJob 能展示 parse、embedding、milvus、opensearch、neo4j 的阶段状态、耗时和错误。
- 真实 LLM/Embedding API 配置错误、网络错误和响应格式错误都能被诊断并落入作业失败原因。
