# V1.7 RAG 模块化优化规划

## 1. 版本目标

V1.7 聚焦“真实 RAG 可调优”：在 V1.6 真实主链路跑通后，把 Query Rewrite、Multi Query、Dense/Sparse/Hybrid/Graph Retrieval、Fusion、Rerank、Context Packing 和 Generation 前后的关键参数显式纳入 Pipeline 配置、运行快照和评估对比。

## 3. 边界

- 不开放任意 Python、HTTP 工具节点或自由 DAG。
- 不把 P08 变成通用低代码编排器；只允许配置受控 RAG 节点和参数。
- 不把模型自动推荐结果直接写入生产配置；优化建议必须可复核。
- 不建设完整 Prompt 管理平台，只固化与 RAG 链路执行相关的参数快照。

## 4. 验收方向

- P08 能配置 Query Rewrite、Dense、Sparse、Hybrid Fusion、Graph Retrieval、Rerank 和 Context Packing 的核心参数。
- QA Run 详情能保存并展示实际使用的 Pipeline Snapshot 和节点级参数。
- 评估集可以对比两个配置版本的命中、引用、答案质量、耗时和失败原因。
- 配置优化建议能说明关联样本、失败原因、建议参数和预期影响，不直接绕过人工确认。

## 5. 调优和复测口径

V1.7 的 RAG 调优参数字典、推荐范围和调参流程已收口到本 Release 记录：

- Query Rewrite / Multi Query：控制查询改写和多查询扩展，优先用于召回不足或问法不稳定的样本。
- Dense / Sparse / Graph Retrieval：重点关注 `topK`、`scoreThreshold`、metadata filter、graph depth 和 expansion limit。
- Hybrid Fusion / Rerank：重点关注融合权重、`rerankTopN`、rerank Provider 可用性和耗时。
- Context Packing / Citation：重点关注 `maxContextTokens`、chunk window、引用约束和权限裁剪后的证据数量。
- QARun 必须保存 `pipelineSnapshot` 和 `nodeParamSnapshot`，评估对比优先读取运行快照，不重新解释当前草稿配置。

调参流程：

1. 选定一组 EvaluationSample，记录基线配置和 QARun 快照。
2. 只调整一个主要参数组，例如召回阈值、融合权重或上下文长度。
3. 对比命中、引用、答案质量、耗时和失败原因。
4. 将优化建议作为草稿供人工复核，不自动上线。

真实环境复测必须覆盖 LLM、Embedding、Milvus、OpenSearch、Neo4j 和 Rerank。复测结论回填到正式发布记录或发布运维手册；`local` / `identity` 只能作为本地降级或环境限制记录，不能替代真实 Provider 发布结论。
