# V1.4 / V1.5 开发准备清单（历史归档）

本文保留 V1.4 / V1.5 真实链路开发前的准备口径。当前 V1.4 和 V1.5 已完成，本文不再作为当前状态源。

## 1. 基线

- 基线分支：`codex/v1.3`
- 目标路线：方案 B，V1.4 真实入库，V1.5 真实检索与回放。
- 不变原则：PostgreSQL 是业务真值中心；Milvus、OpenSearch、Neo4j 都是可重建副本；历史回放不能绕过当前权限。

### 2.4 开发护栏

- 解析失败不得创建成功状态的占位 Chunk。
- IndexSyncJob 只有真实写入成功后才能标记 `success`。
- 外部依赖失败必须记录 provider、阶段、错误摘要和可重试状态。
- Chunk payload 必须统一携带 `chunkId`、`kbId`、`documentId`、`versionId`、`content`、`contentHash`、`pageNo`、`section`、`securityLevel`、`documentStatus`、`versionStatus`、`chunkStatus` 和权限过滤字段。

## 3. V1.5 开发前准备

### 3.1 测试知识库

至少准备一个完整入库成功的知识库：

- 包含 2 个以上文档。
- 每个文档至少 3 个 Chunk。
- 至少一个 Chunk 能被 Dense 命中。
- 至少一个 Chunk 能被 Sparse 命中。
- 至少一组实体关系能通过 Neo4j 回落到 Chunk。
- 至少一条 ACL 或密级场景可触发权限裁剪。

### 3.2 回放样本

至少准备以下 QARun：

| 样本 | 用途 |
| --- | --- |
| 成功 run | 验证回放复跑和结果一致性 |
| partial run | 验证单通道失败后的复跑和诊断对比 |
| permission filtered run | 验证回放时当前权限仍生效 |
| override run | 验证临时参数、channels、topK、temperature 快照 |

### 3.3 开发护栏

- Provider 返回的正文不能直接成为最终 Evidence，必须回表 PostgreSQL。
- Graph Retrieval 结果必须通过 ChunkRef 回落到授权 Chunk。
- 回放只复用上下文和配置快照，不复用历史授权结果。
- local/mock Provider 可以保留为开发兜底，但真实 Provider 配置下不得静默降级为成功。

## 5. 开发顺序建议

1. 先写失败用例和验证脚本，再替换占位逻辑。
2. 先让 PostgreSQL Chunk 真值稳定，再写 Milvus、OpenSearch、Neo4j。
3. 先完成真实检索回表，再接 Fusion/Rerank 和 Generation。
4. 先保存完整回放上下文，再做复跑对比 UI。
