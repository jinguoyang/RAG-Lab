# V1.5 真实检索与回放规划

## 1. 版本目标

V1.5 聚焦“查询时真实全链路”：QA 调试必须基于 V1.4 生成的真实 PostgreSQL、Milvus、OpenSearch 和 Neo4j 数据执行 Dense、Sparse、Graph 检索，经 Fusion/Rerank、Permission Filter、LLM Generation 和 Citation Builder 产出可复现结果，并补齐历史回放、复跑和差异对比。

## 3. 边界

- 不建设公网聊天产品、会话记忆或多轮对话系统。
- 不新增任意 HTTP 工具节点、自定义 Python 节点或自由 DAG。
- 不允许 QA 链路在真实 Provider 配置下自动退回 local/mock 并标记成功；降级必须进入 Trace 和状态。
- 不改变“图结构不是证据真值”的原则，Graph Retrieval 结果必须回落到授权 Chunk。
- 不以页面隐藏替代后端权限裁剪；历史回放和复跑都必须重新执行后端权限判断。

## 4. 验收方向

- P09 执行真实 QA 时，Dense 命中来自 Milvus，Sparse 命中来自 OpenSearch，Graph 命中来自 Neo4j。
- 所有候选进入生成前都回表 PostgreSQL，按当前用户权限和 Chunk 状态裁剪。
- Trace 能展示 query rewrite、embedding、dense、sparse、graph、fusion、rerank、permissionFilter、generation、citation 各阶段。
- Answer 由真实 LLM API 基于授权 Evidence 生成，Citation 可定位到文档、版本、页码、章节和 chunk。
- P10 回放能带回原 query、sourceRunId、configRevisionId、overrideParams、retrieval channels、topK、temperature 和原诊断摘要。
- 回放复跑后能对比原结果和新结果的状态、答案、证据、引用、Trace 指标和配置差异。
