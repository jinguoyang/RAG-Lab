# 中长期规划（历史归档）

本文保留 V1.1 至 V1.7 的路线规划历史。当前 V1.7 已完成，本文不再作为进行中计划的状态源。

后续新版本或新 Epic 开始前，应先更新 [产品待办清单](./产品待办清单.md)，再建立新的 Sprint 或 Release 计划。

## 2. 后续取项原则

- 先确认新增目标属于新 Epic、已有 Epic 的后续 Backlog，还是发布前风险处理。
- 只维护一个状态源：Backlog / Epic 看产品待办清单，Sprint 看 Sprint 总览，Release 看 Release 总览。
- 每个新 Sprint 优先交付一条可运行、可验证的主链路。
- 真实外部 Provider 失败不阻塞本地源码验证，但必须记录诊断结果和环境限制。
- 文档、接口、数据模型和实现如果出现冲突，以 PostgreSQL 业务真值、后端执行契约和可验证脚本为优先。

## 3. 当前观察点

| 观察点 | 影响 | 建议动作 |
| --- | --- | --- |
| 真实 Provider 网络级复测尚未执行 | 不能证明目标环境的 LLM、Embedding、Milvus、OpenSearch、Neo4j、Rerank 可用 | 按发布运维记录补齐复测结果 |
| 前端缺少 lint / test 脚本 | 目前只能以 `npm run build` 作为前端最小验证 | 后续若进入长期维护，可补轻量 lint 或组件测试 |
| 历史规划文档较多 | Agent 容易读到旧计划并误判当前状态 | 以后优先阅读 04 目录 README、产品待办、Sprint 总览和 Release 总览 |
