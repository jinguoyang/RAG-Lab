# 题库按文档分类展示设计

## 1. 文档用途

本文档用于定义外部培训应用题库页面按学习计划内文档分类展示题目的交互和数据处理规则。

本文档是本次功能的设计规范和实施依据，不作为 Backlog、Sprint 或 Release 状态源。

## 2. 目标

题库页面保留现有学习计划筛选能力。用户选择具体学习计划后，页面按照该计划中的文档顺序，将已发布题目分类展示在对应文档下，便于管理员理解题目来源和检查各文档的题目覆盖情况。

## 3. 范围

本次涉及：

- 外部培训应用题库页面的题目分组展示。
- 使用学习计划中的 `documents` 建立 `documentId` 到文档标题的映射。
- 对无法匹配计划文档的题目提供兜底分组。
- 补充与分组逻辑直接相关的前端测试。

本次不涉及：

- 不新增数据库表或字段。
- 不修改题目生成、审核、发布、修改和删除流程。
- 不改变题目与计划、文档的归属规则。
- 不修改题目列表接口返回结构。
- 不改造题库审核页面和课堂答题页面。

## 4. 数据来源

题目列表继续通过现有接口按计划和发布状态查询：

```text
GET /training/questions?planId={planId}&status=published
```

分组所需数据来自现有字段：

- `TrainingQuestion.documentId`：题目所属文档 ID。
- `TrainingPlan.documents[].documentId`：计划内文档 ID。
- `TrainingPlan.documents[].title`：页面展示的文档标题。

前端不得根据题干、Evidence 文本或文档标题猜测题目归属。

## 5. 页面交互

### 5.1 选择具体学习计划

用户选择具体学习计划后：

1. 页面按计划 `documents` 数组顺序展示文档分组。
2. 每个存在已发布题目的文档显示一个分组。
3. 分组标题显示文档标题和该分组题目数量。
4. 分组内部沿用现有题目卡片、编辑和删除交互。
5. 某份计划文档没有已发布题目时，不展示空分组。

### 5.2 选择全部计划

选择“全部计划”时维持现有题目平铺展示，不跨计划按 `documentId` 合并，避免相同文档被多个计划引用时产生归属歧义。

### 5.3 未关联文档

选定计划后，出现以下任一情况的题目归入“未关联文档”分组：

- `documentId` 为空。
- `documentId` 不存在于当前计划的 `documents` 中。

“未关联文档”分组排列在所有正常文档分组之后。该分组只提供可见性，不自动修正题目归属。

## 6. 前端处理

题库页面根据当前选中的计划构建文档映射，并通过 `useMemo` 计算展示分组：

```text
当前计划 documents
        +
已发布 questions
        |
        v
按 documentId 分组
        |
        +-- 计划文档顺序
        |
        +-- 未关联文档兜底
```

实现应保持局部：

- 不改变 `listQuestions` 的参数和返回类型。
- 不引入新的全局状态或抽象层。
- 编辑或删除题目后，使用当前页面状态重新计算分组。
- 删除某分组最后一道题后，该空分组自动消失。

## 7. 异常与空状态

- 查询失败：沿用当前错误提示。
- 选定计划且没有已发布题目：沿用“题库暂无题目”空状态。
- 计划文档标题为空：使用 `documentId` 作为分组标题。
- 当前计划未找到：退化为平铺展示，避免页面崩溃。

## 8. 验收标准

- 选择具体学习计划后，题目按该计划中的文档分类展示。
- 文档分组顺序与学习计划文档顺序一致。
- 分组标题能展示文档名称和题目数量。
- 无关联或无法匹配的题目进入“未关联文档”分组。
- 选择“全部计划”时仍按当前方式平铺展示。
- 题目修改和删除功能保持可用。
- 未新增数据库迁移，现有题目接口契约不变。
- 前端相关测试通过，`npm run build` 成功。
