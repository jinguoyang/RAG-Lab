# 三方员工培训接入验证流程

> 本文是活文档，用于说明外部系统接入平台员工培训 Agent 时的 App API Key 验证流程和接口契约。本文只覆盖 `/api/v1/training/` 三方调用，不替代管理端 RAG App、API Key 和审计接口设计。

## 1. 接入目标

三方系统通过平台生成的 App API Key 调用员工培训 Agent 能力。平台根据 Key 反查所属 App，并使用该 App 绑定的知识库、配置版本和员工培训场景配置执行学习计划、题库和课堂流程。

三方请求体不传 `appId`。`appId` 是平台侧资源归属和响应审计字段，不是三方调用参数。

## 2. 凭据发放

1. 平台管理员创建或选择员工培训类型 RAG App。
2. 平台确认该 App 绑定了可用知识库和可运行配置版本。
3. 平台管理员在 App 管理页生成 App API Key。
4. 平台只在创建响应中返回一次 Key 明文，数据库仅保存 `sha256(plaintext_key)`、`key_prefix`、状态、过期时间和审计字段。
5. 三方系统后端保存 Key；浏览器端、移动端和日志中不得保存或展示 Key 明文。

## 3. 调用契约

三方系统调用员工培训接口时统一使用：

```http
Authorization: Bearer <app_api_key>
Content-Type: application/json
```

请求体不包含 `appId`，典型请求如下：

```json
{
  "jobTitle": "安全员",
  "jobDescription": "负责工厂安全"
}
```

平台响应仍包含 `appId`：

```json
{
  "planId": "平台生成的计划草稿 ID",
  "appId": "Key 所属 App ID",
  "jobTitle": "安全员",
  "status": "draft"
}
```

## 4. 平台验证流程

平台收到请求后按以下顺序验证：

1. 从 `Authorization` 解析 Bearer Token，缺失或格式错误返回 `APP_API_KEY_INVALID`。
2. 对明文 Key 计算 SHA-256，查询 `rag_app_api_keys.key_hash`。
3. 校验 Key 存在、状态为 `active`、未过期。
4. 读取 Key 所属 `rag_apps` 记录，校验 App 存在、未删除、状态为 `active`。
5. 校验 App 元数据中的 `scenario.scenarioType` 为 `employee_training`。
6. 读取 App 绑定知识库，校验知识库存在、未删除、可用。
7. 解析 App 默认配置版本；若缺省则回退知识库 active revision；草稿或无效版本返回 `RAG_APP_NO_RUNNABLE_REVISION`。
8. 使用解析出的 `app_id` 执行业务逻辑；不得接受请求体传入的 `appId` 来切换 App。
9. 对后续资源操作继续校验归属关系，例如 `sessionId`、`planId`、`questionId` 必须属于当前 Key 所属 App。

## 5. 外部应用保存边界

外部应用可以保存：

- 平台地址。
- App API Key 的服务端配置或安全引用。
- 平台返回的 `appId`、计划、题目和课堂会话镜像。
- 本地审核任务、课堂展示记录和答题 UI 状态。

外部应用不得保存：

- App API Key 明文到浏览器端。
- Prompt、Trace、LLM 原始响应。
- Chunk 正文或未经授权的文档正文。
- 用于切换 App 的自定义 `appId` 请求参数。

## 6. 验收标准

- 三方调用 `training/plans/drafts` 时，请求体不携带 `appId` 也能生成平台计划草稿。
- 三方调用 `training/questions/drafts` 时，请求体不携带 `appId` 也能生成题库草稿。
- 三方调用 `training/classroom/sessions` 时，请求体不携带 `appId` 也能创建课堂会话。
- 使用 App B 的 Key 操作 App A 的 `sessionId`、`planId` 或 `questionId` 时必须失败。
- 外部应用的配置页和服务端 `.env` 只要求平台地址和 App API Key。
