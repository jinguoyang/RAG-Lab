# 章节级交互式课程蓝图设计规范

> 用途：本文定义员工培训 Agent 从“Chunk 改写课堂”升级为“整篇理解、章节组织、脚本授课、对话互动”的初版设计。Backlog 状态仍以 `docs/04-迭代与交付/产品待办清单.md` 为准。

## 1. 目标

参考以下验收样例：

- `docs/05-测试与验收/examples/呆滞物料管理办法-教案.md`
- `docs/05-测试与验收/examples/呆滞物料管理办法-讲稿.md`

课堂应达到以下效果：

- 先理解整篇制度的目的、适用范围、核心概念、职责、流程、风险和改进要求，再决定课程结构。
- 长文档按业务章节或可验证学习目标拆节，短文档允许保持一个完整小节。
- 教学正文使用连贯讲稿，不展示 Chunk 编号、证据包或大段原文。
- Chunk 继续作为事实依据、Citation 和受控答疑边界，但不是面向学员的教学组织单位。
- 用户在同一课堂页面内完成讲解、追问、Checkpoint、反馈、下一节和课程总结。
- 会话保存当前小节、历史消息、待答题目和已完成小节，退出后二次进入可继续。

## 2. 关键假设

- PostgreSQL 中的 Chunk 仍是证据真值，不改变现有 RAG 与权限边界。
- 课程蓝图和章节讲稿保存在学习计划现有 JSON/metadata 中，初版不新增数据库表。
- 计划生成阶段可以读取入选文档的全部有效 Chunk，并按 `section_path`、`section`、`heading` 和顺序恢复文档结构。
- 课堂运行优先使用冻结课程快照中的讲稿；计划发布后，课堂中途不因文档重新切块而漂移。
- 自由追问和错题解释继续调用当前章节范围内的 RAG，不允许脱离课程证据编造要求。

## 3. 方案

采用“预生成课程蓝图 + 运行时受控互动”：

```text
检索候选文档
  -> 读取入选文档全部有效 Chunk
  -> 按文档与章节聚合为内部内容地图
  -> LLM 生成课程蓝图和章节讲稿
  -> 程序校验来源、结构和质量分
  -> 管理员审核并发布
  -> 课堂按冻结讲稿连续授课
  -> 追问/错题时按当前章节证据调用 RAG
```

不采用以下方案：

- 每次进入课堂都把整篇文档重新交给模型：延迟高，恢复结果不稳定。
- 课堂直接拼接多个 Chunk 再让模型临场改写：仍会保留 Chunk 边界，讲解容易重复和断裂。
- 只播放固定讲稿：无法支持自由追问、针对性反馈和 Checkpoint。

## 4. 数据契约

`LearningSectionDTO` 在现有字段基础上增加 `teachingScript`：

```json
{
  "sectionId": "section-001",
  "title": "识别呆滞物料",
  "learningObjective": "能够根据库存状态判断物料是否需要进入呆滞评审。",
  "sourceDocumentIds": ["document-id"],
  "evidenceChunkIds": ["chunk-1", "chunk-2"],
  "keyPoints": ["七类判定条件", "异动率", "呆滞不等于废品"],
  "checkpointCriteria": ["能判断典型场景", "能说明判断依据"],
  "teachingScript": {
    "opening": "仓库中一批电子元器件三年只领用了少量，你会先直接报废吗？",
    "explanation": "连贯讲解本节概念、关系、边界和工作方法，不复制原文。",
    "scenario": "包含人物、物料状态、判断过程和正确动作的具体案例。",
    "interactionQuestions": ["质量合格的物料为什么仍可能呆滞？"],
    "summary": "本节需要带走的判断原则和行动顺序。"
  },
  "teachingQualityScore": 0.82,
  "estimatedMinutes": 12,
  "required": true
}
```

约束：

- `teachingScript` 不得包含 `chunkId`、`参考证据`、`证据包`等内部实现词。
- `explanation` 不得由单个 Chunk 原文直接充当；应解释概念关系、工作顺序和边界。
- `sourceDocumentIds` 与 `evidenceChunkIds` 必须来自当前 App 可访问范围。
- `interactionQuestions` 初版为 1 至 3 个，引导思考但不替代 Checkpoint。
- `teachingQualityScore` 由程序重新计算，不信任模型自报分数。

## 5. 课堂输出

正常小节按以下形式输出：

```text
小节标题与学习目标

情境导入
用一个岗位相关问题说明为什么要学。

教师讲解
按概念、判断依据、职责或流程关系连贯讲解。

工作案例
给出具体情境、判断过程和正确动作。

想一想
给出一至两个可继续对话的问题。

本节小结
提炼行动原则，随后进入 Checkpoint。
```

课堂正文不附原始 Chunk 文本。Citation 作为结构化字段保留，后续可通过“查看依据”按需展开。

## 6. 质量门槛

初版质量分满分为 1，至少覆盖：

| 维度 | 权重 | 判定 |
| --- | ---: | --- |
| 教学结构完整 | 0.25 | 导入、讲解、案例、互动、小结齐全 |
| 章节目标一致 | 0.20 | 标题、目标、关键点和验收标准相互对应 |
| 内容条理性 | 0.20 | 包含概念关系、流程顺序或职责边界，不是条文堆砌 |
| 场景可执行 | 0.15 | 案例包含具体条件、判断和行动 |
| 非 Chunk 化 | 0.20 | 不暴露内部标签，且与任一证据片段不存在大段直接重合 |

验收规则：

- 单节分数低于 `0.7` 时，计划生成应记录质量不足并使用一次修复提示；修复后仍不足则保留草稿但标记不可发布。
- 本轮初版验收以《呆滞物料管理办法》样例课程平均分不低于 `0.7` 为准。
- 自动评分只作为工程门槛，仍需浏览器人工检查流程是否通顺、内容是否像讲稿。

## 7. 连续流程与恢复

- 创建或恢复课堂后自动进入当前小节，不要求用户返回计划页再进入。
- 讲解页始终保留课程进度、小节目标、预计时长和保存退出。
- 完成 Checkpoint 后在当前页展示反馈，并直接提供下一节或完成课程。
- 恢复时以服务端会话为准，重建当前讲稿、历史消息、待答动作和进度。
- 课程完成前不展示不可执行的完成按钮。

## 8. 错误处理

- 全文内容不足：返回“课程材料不足”，不使用通用空泛讲稿冒充真实教学。
- LLM 输出无法解析：允许规则化生成课程结构，但讲稿标记为待审核，不自动达到质量门槛。
- 章节证据失效：已开始的课堂使用冻结脚本继续；追问时若无可用证据，明确提示无法核实。
- 恢复失败：清除无效本地会话 ID，创建新会话并提示用户，而不是停留在空白页。

## 9. 验收场景

1. 《呆滞物料管理办法》长文档可形成围绕“为什么管理、如何识别、谁负责、流程如何走、如何处置与改进”的有序课程。
2. 课堂讲稿与参考讲稿形式接近，但不要求逐字一致。
3. 页面内可以连续完成多个小节，无繁杂返回和重新进入。
4. 在 Checkpoint 页面关闭课堂，重新进入后仍停留在同一题目和小节。
5. 教学正文中不出现 Chunk 列表或大段“参考证据”原文。
