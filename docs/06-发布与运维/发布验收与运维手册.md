# 发布验收与运维手册

## 1. 本地环境部署

本地开发环境用于验证 V1.0 最小闭环，不直接作为生产运行环境。

1. 前端：进入 `frontend/` 后执行 `npm install`、`npm run build` 或 `npm run dev`。
2. 后端：进入 `backend/` 后执行 `conda env update -f environment.yml --prune`。
3. 配置：复制 `backend/.env.example` 为 `backend/.env`，至少配置 `RAG_LAB_DATABASE_URL`。
4. 数据库：执行 `backend/scripts/migrate.ps1` 应用 Alembic 迁移。
5. 启动：执行 `backend/scripts/start-dev.ps1`，访问 `/api/v1/health` 做基础探活。

## 2. 测试环境部署

测试环境沿用本地工程结构，但必须使用独立数据库和对象存储命名空间。

- `RAG_LAB_ENVIRONMENT` 设置为 `test`。
- 数据库连接使用测试专用 PostgreSQL，迁移完成后再导入种子数据。
- 外部 Provider 可先使用 `local` / `identity` 占位，接入真实 MinIO、Milvus、OpenSearch、Neo4j、LLM 前必须更新 `.env`。
- 发布前执行后端编译、OpenAPI 导出、基础健康检查和前端构建。

## 3. 外部依赖健康检查

后端提供 `GET /api/v1/health/dependencies` 返回依赖配置摘要。该接口只检查配置完整性，不主动发起外部网络探测，避免发布检查因 Provider 慢响应阻塞。

重点关注：

- `postgres` 为 `configured` 时表示已配置 `RAG_LAB_DATABASE_URL`。
- `object_storage` 为 `local` 表示仅保存元数据，不写真实对象存储。
- `embedding`、`dense_retrieval`、`sparse_retrieval`、`graph_retrieval`、`llm`、`rerank` 会返回当前 Provider 名称。

## 4. 备份恢复

PostgreSQL 是业务真值中心，备份恢复必须优先覆盖数据库。

- 备份：使用 `pg_dump` 导出业务库，并同步备份对象存储 bucket 中的原始文件。
- 恢复：先恢复 PostgreSQL，再恢复对象存储，最后按需重建 Milvus、OpenSearch 和 Neo4j 副本。
- 校验：恢复后执行迁移状态检查、`/api/v1/health/dependencies`、文档详情、QA 历史和图检索分析的抽样读取。
- 回滚：若新版本迁移失败，停止服务，恢复上一份数据库备份和对象存储快照，再启动上一版本镜像或代码包。
- 备份恢复演练记录：演练完成后通过 `POST /api/v1/knowledge-bases/{kbId}/backup-drills` 回填结果，列表通过 `GET /api/v1/knowledge-bases/{kbId}/backup-drills` 查询；记录必须包含 `restoredObjects`、`residualRisks`、演练结果和可追溯证据。

## 6. 审计排障

高风险操作通过 `GET /api/v1/audit-logs` 查询，支持按 `kbId`、`action`、`resourceType`、`resourceId`、`actorId`、`createdFrom`、`createdTo` 和 `keyword` 过滤。

非平台管理员必须指定 `kbId`，且只能查询自己具备 `kb.view` 权限的知识库日志。

## 7. 真实 RAG 与 Provider 复测

阶段性 `verify_*.py` 脚本已归档清理；后续发布复测以真实环境记录为准，不再维护单独的历史复测模板。

真实 RAG 与 Provider 复测必须覆盖：

- 文档上传、解析、Chunk 切分、Embedding、索引副本写入。
- Dense、Sparse、Graph 检索候选回表 PostgreSQL 和权限裁剪。
- Query Rewrite、Rerank、Generation、Citation、Trace 和回放复跑。
- LLM、Embedding、Milvus、OpenSearch、Neo4j 和 Rerank 的连通性、鉴权、限流、响应格式和耗时。

复测结论应记录在正式发布记录或本手册的版本补充段落中。任一 Provider 未配置、不可达、鉴权失败、限流或响应格式异常，都应标为环境限制或发布风险；不得改用 `local`、`mock` 或 `identity` 成功结果替代真实环境结论。

V1.8 起可使用以下脚本生成真实 Provider 网络级复测证据：

```powershell
cd backend
conda run -n rag-lab python scripts/verify_provider_network_retest.py --output ..\docs\06-发布与运维\V1.8-Provider网络级复测记录.json --strict
```

脚本覆盖 Embedding、Milvus、OpenSearch、Neo4j、LLM 和 Rerank。`success` 表示对应真实 Provider 网络探测通过；`local_provider`、`blocked`、`missing_dependency`、`timeout`、`auth_failed`、`rate_limited` 或 `format_error` 都不能作为真实复测通过。V1.8 Sprint 32 的执行结论见 [V1.8 Provider 网络级复测记录](./V1.8-Provider网络级复测记录.md)。

## 8. V1.8 App Runtime 最小调用

外部 Web 应用通过管理端创建 RAG App 和 App API Key 后，可调用 blocking 对话接口：

```powershell
$headers = @{ Authorization = "Bearer <app_api_key>" }
$body = @{
  query = "请基于知识库回答这个问题"
  endUserId = "external-user-001"
  responseMode = "blocking"
} | ConvertTo-Json
Invoke-RestMethod -Method Post -Uri "http://127.0.0.1:8000/api/v1/app-runtime/chat-messages" -Headers $headers -ContentType "application/json" -Body $body
```

成功响应包含 `answer`、`citations`、`conversationId`、`messageId`、`runId`、`usage` 和 `metadata`。`citations` 只返回经 QARun 权限裁剪后的安全引用摘要，完整 Trace 仍通过平台内部 QA 历史查看。

如需 SSE 输出，将 `responseMode` 设置为 `streaming`。服务端返回 `text/event-stream`，事件类型包括 `answer_delta`、`citation`、`usage` 和 `done`；该模式仍复用 QARun 执行链路并写入 App Message 与 Invocation。

应用级限流和配额使用 RAG App 的 `metadata.runtimeLimits` 或 `outputPolicy.runtimeLimits` 配置，当前支持：

- `minuteLimit` 或 `requestsPerMinute`：短窗口调用上限。
- `dailyQuota` 或 `dailyRequestQuota`：UTC 自然日成功调用配额。

超限时接口返回 HTTP 429 和 `RAG_APP_QUOTA_EXCEEDED`，并写入 failed invocation 审计。管理端或运维可通过 `GET /api/v1/rag-apps/{appId}/stats` 查看总调用、失败率、平均延迟、限流次数和无证据率。

外部反馈通过以下接口回流到内部治理链路：

```powershell
$feedback = @{
  feedbackStatus = "wrong"
  feedbackNote = "外部用户反馈答案不匹配"
  failureType = "answer_mismatch"
  createEvaluationSample = $true
} | ConvertTo-Json
Invoke-RestMethod -Method Post -Uri "http://127.0.0.1:8000/api/v1/app-runtime/messages/<message_id>/feedback" -Headers $headers -ContentType "application/json" -Body $feedback
```

反馈只允许写回当前 App 的助手消息；可同步更新 QARun 反馈并沉淀 EvaluationSample，但不会向外部响应暴露 Trace、Evidence 正文或内部配置。
